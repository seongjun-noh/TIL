## JUnit 5 기초

### JUnit 5 구성요소
- JUnit Platform: 테스트를 실행하기 위한 기반 역할
- JUnit Jupiter: JUnit 5의 새로운 프로그래밍 모델과 확장 모델
- JUnit Vintage: JUnit 3, 4를 지원하기 위한 테스트 엔진

### 기본 어노테이션

#### 테스트 라이프사이클
- `@Test`: 테스트 메서드임을 나타냄
- `@BeforeEach`: 각각의 테스트 메서드 실행 전에 실행
- `@AfterEach`: 각각의 테스트 메서드 실행 후에 실행
- `@BeforeAll`: 모든 테스트 실행 전에 한 번만 실행 (static 메서드에 사용)
- `@AfterAll`: 모든 테스트 실행 후에 한 번만 실행 (static 메서드에 사용)

```java
class LifecycleTest {
    @BeforeAll
    static void setupAll() {
        // 모든 테스트 전에 한 번만 실행
    }
    
    @BeforeEach
    void setupEach() {
        // 각 테스트 전에 실행
    }
    
    @Test
    void test1() {
        // 테스트 코드
    }
    
    @AfterEach
    void tearDownEach() {
        // 각 테스트 후에 실행
    }
    
    @AfterAll
    static void tearDownAll() {
        // 모든 테스트 후에 한 번만 실행
    }
}
```

#### 테스트 실행 제어
- `@Disabled`: 테스트 클래스나 메서드를 비활성화
```java
@Disabled("해당 기능 구현 전까지 테스트 비활성화")
@Test
void disabledTest() {
    // 테스트 코드
}
```

- `@Timeout`: 테스트 실행 시간 제한 설정
```java
@Test
@Timeout(value = 500, unit = TimeUnit.MILLISECONDS)
void timeoutTest() {
    // 500ms 이내에 완료되어야 하는 테스트
}
```

### 테스트 실행 최적화

#### 반복 테스트
- `@RepeatedTest`: 테스트를 지정된 횟수만큼 반복
```java
@RepeatedTest(5)
void repeatedTest() {
    // 5번 반복될 테스트
}
```

- `@ParameterizedTest`: 다양한 매개변수로 테스트 실행
```java
@ParameterizedTest
@ValueSource(strings = {"test1", "test2", "test3"})
void parameterizedTest(String param) {
    assertNotNull(param);
}
```

#### 테스트 실행 순서 제어
```java
@TestMethodOrder(MethodOrderer.OrderAnnotation.class)
class OrderedTestsDemo {
    @Test
    @Order(1)
    void firstTest() {
        // 첫 번째로 실행되어야 하는 테스트
    }
    
    @Test
    @Order(2)
    void secondTest() {
        // 두 번째로 실행되어야 하는 테스트
    }
}
```

#### 테스트 그룹화
```java
@Tag("integration")

}

@Tag("unit")

    // 단위 테스트 구현

```

## 테스트 검증

### 기본 검증 메서드
```java
@Test
void basicAssertions() {
    // 동일성 검증
    assertEquals(expected, actual);
    assertNotEquals(unexpected, actual);
    
    // null 검증
    assertNull(actual);
    assertNotNull(actual);
    
    // 조건 검증
    assertTrue(condition);
    assertFalse(condition);
    
    // 예외 검증
    assertThrows(ExpectedException.class, () -> {
        // 예외가 발생해야 하는 코드
    });
}
```

### 컬렉션 검증
```java
@Test
void collectionAssertions() {
    List<String> list = Arrays.asList("a", "b", "c");
    
    // 컬렉션 크기 검증
    assertEquals(3, list.size());
    
    // 컬렉션 내용 검증
    assertTrue(list.contains("a"));
    assertFalse(list.contains("d"));
    
    // 컬렉션 순서 검증
    assertEquals("a", list.get(0));
    assertEquals("b", list.get(1));
    assertEquals("c", list.get(2));
}
```

### 객체 검증
```java
@Test
void objectAssertions() {
    User user = new User("test@test.com", "password");
    
    // 객체 속성 검증
    assertAll("user properties",
        () -> assertEquals("test@test.com", user.getEmail()),
        () -> assertEquals("password", user.getPassword())
    );
}
```

## 모범 사례

### 테스트 구조화
1. Given (준비)
   - 테스트 데이터 준비
   - 테스트 환경 설정

2. When (실행)
   - 테스트 대상 메서드 호출
   - 테스트 동작 수행

3. Then (검증)
   - 결과값 검증
   - 상태 검증

### 테스트 네이밍 컨벤션
- 메서드명_테스트조건_기대결과
- 예: `createUser_ValidInput_ReturnsUser()`
