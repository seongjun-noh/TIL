## 1. 로깅이란?

### 로깅의 개념
로깅은 프로그램이 실행되는 동안 발생하는 모든 활동을 기록하는 것입니다. 마치 일기를 쓰는 것처럼, 애플리케이션에서 일어나는 모든 중요한 일들을 기록합니다.

### 로깅이 필요한 이유
1. **문제 해결**: 오류가 발생했을 때 원인을 쉽게 찾을 수 있습니다
2. **모니터링**: 애플리케이션의 상태를 실시간으로 확인할 수 있습니다
3. **분석**: 사용자의 행동과 시스템 성능을 분석할 수 있습니다

## 2. 로그 레벨 이해하기

### 로그 레벨 종류
1. **ERROR**: 
   - 매우 심각한 문제 발생
   - 예: 서버 다운, 데이터베이스 연결 실패
   
2. **WARN**: 
   - 주의가 필요한 상황
   - 예: 디스크 공간 부족, 성능 저하
   
3. **INFO**: 
   - 일반적인 정보
   - 예: 사용자 로그인, 주요 기능 실행
   
4. **DEBUG**: 
   - 개발자를 위한 상세 정보
   - 예: 변수값, 함수 호출 정보
   
5. **TRACE**: 
   - 가장 상세한 정보
   - 예: 모든 프로세스의 세부 단계

## 3. 기본 로그 설정하기 (Logback)

### 간단한 로그백 설정
```xml
<?xml version="1.0" encoding="UTF-8"?>
<configuration>
    <!-- 콘솔에 로그 출력하기 -->
    <appender name="CONSOLE" class="ch.qos.logback.core.ConsoleAppender">
        <encoder>
            <pattern>%d{yyyy-MM-dd HH:mm:ss} [%thread] %-5level %logger{36} - %msg%n</pattern>
        </encoder>
    </appender>

    <!-- 파일에 로그 저장하기 -->
    <appender name="FILE" class="ch.qos.logback.core.rolling.RollingFileAppender">
        <file>logs/application.log</file>
        <rollingPolicy class="ch.qos.logback.core.rolling.TimeBasedRollingPolicy">
            <fileNamePattern>logs/application.%d{yyyy-MM-dd}.log</fileNamePattern>
            <maxHistory>30</maxHistory>
        </rollingPolicy>
        <encoder>
            <pattern>%d{yyyy-MM-dd HH:mm:ss} [%thread] %-5level %logger{36} - %msg%n</pattern>
        </encoder>
    </appender>

    <!-- 기본 로그 레벨 설정 -->
    <root level="INFO">
        <appender-ref ref="CONSOLE" />
        <appender-ref ref="FILE" />
    </root>
</configuration>
```

### 로그 패턴 설명
- `%d{yyyy-MM-dd HH:mm:ss}`: 날짜와 시간
- `[%thread]`: 실행 중인 스레드 이름
- `%-5level`: 로그 레벨
- `%logger{36}`: 로거 이름
- `%msg%n`: 로그 메시지와 줄바꿈

## 4. 실제 로그 작성 예시

### 자바 코드에서 로그 사용하기
```java
@Slf4j  // Lombok을 사용할 경우
@RestController
public class UserController {
    
    @GetMapping("/users/{id}")
    public User getUser(@PathVariable Long id) {
        // 일반 정보 로깅
        log.info("사용자 정보 조회 시작: ID = {}", id);
        
        try {
            User user = userService.getUser(id);
            // 디버그 정보 로깅
            log.debug("조회된 사용자 정보: {}", user);
            return user;
        } catch (Exception e) {
            // 에러 정보 로깅
            log.error("사용자 조회 실패: ID = {}", id, e);
            throw e;
        }
    }
}
```

## 5. 로그 모니터링 도구 (ELK 스택) 이해하기

### ELK 스택이란?
ELK는 세 가지 오픈소스 도구의 조합입니다:

1. **Elasticsearch**
   - 로그를 저장하고 검색하는 데이터베이스
   - 빠른 검색과 분석 기능 제공

2. **Logstash**
   - 로그를 수집하고 가공하는 도구
   - 여러 소스의 로그를 통합 관리

3. **Kibana**
   - 로그를 시각적으로 보여주는 대시보드
   - 그래프, 차트로 데이터 표현

## 6. 로깅 모범 사례

### 기본 원칙
1. **필요한 정보만 기록하기**
   - 너무 많은 로그는 성능에 영향을 줄 수 있음
   - 중요한 정보를 선별해서 기록

2. **명확한 메시지 작성**
   - 누가 봐도 이해할 수 있게 작성
   - 상황 설명과 관련 데이터 포함

3. **민감 정보 보호**
   - 비밀번호, 개인정보는 절대 로그에 기록하지 않기
   - 필요한 경우 마스킹 처리

4. **로그 관리**
   - 정기적인 로그 파일 정리
   - 저장 공간 관리
