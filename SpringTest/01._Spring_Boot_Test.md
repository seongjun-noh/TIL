# Spring Boot 테스트

## 1. 테스트의 기본 개념

> [!note] Spring Boot 테스트란?
> Spring Boot 애플리케이션은 결국 Spring ApplicationContext이므로, 일반적인 Spring 컨텍스트 테스트 방식을 그대로 사용할 수 있습니다.
> 다만 Spring Boot의 추가 기능(외부 설정, 로깅 등)을 테스트에서 사용하려면 `SpringApplication`을 통해 컨텍스트를 생성해야 합니다.

### spring-boot-starter-test

테스트에 필요한 다음 핵심 라이브러리들을 자동으로 포함합니다:

| 라이브러리                                                                                                            | 설명                                    |
| ---------------------------------------------------------------------------------------------------------------- | ------------------------------------- |
| [JUnit 5](https://junit.org/junit5/)                                                                             | Java 애플리케이션의 표준 단위 테스트 프레임워크          |
| [Spring Test](https://docs.spring.io/spring-framework/reference/6.2/testing/integration.html) & Spring Boot Test | Spring Boot 전용 테스트 유틸리티와 통합 테스트 기능 제공 |
| [AssertJ](https://assertj.github.io/doc/)                                                                        | 직관적인 문법의 Fluent Assertion 라이브러리       |
| [Hamcrest](https://github.com/hamcrest/JavaHamcrest)                                                             | Matcher 기반의 제약조건 검증 라이브러리             |
| [Mockito](https://site.mockito.org/)                                                                             | Java 기반 객체 모킹 프레임워크                   |
| [JSONassert](https://github.com/skyscreamer/JSONassert)                                                          | JSON 데이터 검증 라이브러리                     |
| [JsonPath](https://github.com/jayway/JsonPath)                                                                   | JSON 데이터 추출 라이브러리 (XPath 스타일)         |
| [Awaitility](https://github.com/awaitility/awaitility)                                                           | 비동기 로직 테스트를 위한 대기/조건 검증 라이브러리         |

> [!tip] JUnit 버전별 주의사항
> - JUnit 4 사용 시: `@RunWith(SpringRunner.class)` 필수
> - JUnit 5 사용 시: `@ExtendWith(SpringExtension.class)` 불필요 (테스트 어노테이션에 이미 포함)

## 2. @SpringBootTest 상세 가이드

### 기본 동작 이해하기

> [!important] 핵심 특징
> 1. 실제 애플리케이션과 유사한 테스트 환경 제공
> 2. 전체 ApplicationContext 로드
> 3. 기본적으로 서버 시작하지 않음
> 4. `@SpringBootApplication` 클래스를 설정으로 사용

### main() 메서드 실행 설정 (Spring Boot 3.2+)

#### 1. 기본 동작
- `@SpringBootApplication` 클래스만 참조
- `main()` 메서드는 호출하지 않음

#### 2. main() 메서드가 중요한 경우
다음과 같이 `main()`에서 중요 설정을 하는 경우:

```java
public static void main(String[] args) {
    SpringApplication app = new SpringApplication(MyApplication.class);
    app.setBannerMode(Banner.Mode.OFF);
    app.setAdditionalProfiles("myprofile"); // 프로파일 설정
    app.run(args);
}
```

#### 3. useMainMethod 옵션 사용하기

| 옵션 | 설명 | 사용 시점 |
|------|------|-----------|
| NEVER (기본값) | main() 미호출 | 일반적인 테스트 |
| WHEN_AVAILABLE | main() 있으면 호출 | 선택적 main() 설정 필요 시 |
| ALWAYS | main() 필수 호출 | main() 설정이 반드시 필요한 경우 |

```java
@SpringBootTest(useMainMethod = UseMainMethod.ALWAYS)
class MyApplicationTests {
    @Test
    void testSomething() {
        // main()의 설정이 반영된 ApplicationContext 사용
    }
}
```

### webEnvironment 설정 옵션

#### 1. MOCK (기본값)
- 목적: 컨트롤러 단위 테스트
- 특징: 
  - 실제 서버 대신 Mock 환경
  - `@AutoConfigureMockMvc`와 함께 사용
  - 웹 환경 없으면 일반 컨텍스트로 대체

#### 2. RANDOM_PORT
- 목적: 실제 HTTP 통합 테스트
- 특징:
  - 실제 내장 서버 시작
  - 랜덤 포트 사용
  - `@LocalServerPort`로 포트 주입

#### 3. DEFINED_PORT
- 목적: 특정 포트로 테스트
- 특징:
  - 지정된 포트로 서버 시작 (기본: 8080)
  - application.properties 포트 설정 사용

#### 4. NONE
- 목적: 서비스/레포지토리 단위 테스트
- 특징:
  - 웹 환경 없이 컨텍스트만 로드
  - 가장 가벼운 설정

> [!warning] 트랜잭션 관리 주의사항
> 1. `@Transactional` 테스트는 자동 롤백
> 2. RANDOM_PORT/DEFINED_PORT 사용 시:
>    - 별도 스레드에서 실행
>    - 롤백 적용 안됨
>    - DB 초기화 전략 필요

## 3. 테스트 구성 최적화

### 웹 애플리케이션 타입 감지 순서

> [!tip] 자동 감지 우선순위
> 1. Spring MVC 존재 → MVC 기반 구성
> 2. WebFlux만 존재 → WebFlux 기반 구성
> 3. 둘 다 존재 → MVC 우선 (WebFlux 테스트는 명시적 설정 필요)

WebFlux 테스트 설정:
```properties
spring.main.web-application-type=reactive
```

### 효율적인 테스트 설정 관리

#### 1. 기본 원칙
- `@SpringBootApplication` 클래스는 핵심 설정만 포함
- 영역별 설정은 별도 `@Configuration` 클래스로 분리

#### 2. 설정 분리 예시
```java
@Configuration(proxyBeanMethods = false)
@EnableMongoAuditing
public class MongoTestConfig {
    // MongoDB 관련 설정
}
```

> [!caution] 슬라이스 테스트 주의사항
> 1. `@WebMvcTest`, `@DataJpaTest` 등에서 `@ComponentScan` 직접 사용 지양
> 2. 직접 사용 시 문제점:
>    - 자동 exclude 필터 무시
>    - 불필요한 빈 로드
>    - 성능 저하
>    - 예상치 못한 테스트 실패

## 4. 테스트 설정과 슬라이스

### 테스트 설정 구성 원칙

> [!important] 핵심 원칙
> 1. `@SpringBootApplication` 클래스는 공통 설정만 포함
> 2. 특정 영역의 설정은 별도 클래스로 분리
> 3. 슬라이스 테스트에서는 필요한 설정만 선택적으로 포함

### 잘못된 설정 예시

MongoDB 감사 기능을 메인 애플리케이션 클래스에 직접 설정:

```java
@SpringBootApplication
@EnableMongoAuditing  // 👎 메인 클래스에 특정 기능 설정
public class MyApplication {
    // ...
}
```

이 경우의 문제점:
- 모든 슬라이스 테스트에서 MongoDB 감사 기능 활성화 시도
- 불필요한 설정이 테스트에 포함됨
- 테스트 실행 속도 저하

### 권장되는 설정 방식

영역별로 설정 분리:

```java
@Configuration(proxyBeanMethods = false)
@EnableMongoAuditing
public class MongoConfig {  // 👍 별도 설정 클래스
    // MongoDB 관련 설정
}
```

장점:
- 필요한 테스트에서만 `@Import`로 설정 포함 가능
- 설정의 모듈화와 재사용성 향상
- 테스트 실행 속도 개선

### 컴포넌트 스캔 설정

#### 1. 잘못된 방식
```java
@SpringBootApplication
@ComponentScan({"com.example.app", "com.example.another"})  // 👎 메인 클래스에 직접 설정
public class MyApplication {
    // ...
}
```

문제점:
- 모든 슬라이스 테스트에서 추가 패키지까지 스캔
- `@DataJpaTest` 등에서 불필요한 컴포넌트 로드
- 테스트 격리 원칙 위반

#### 2. 권장되는 방식
별도의 설정 클래스 사용:

```java
@Configuration
@ComponentScan({"com.example.another"})  // 👍 별도 클래스로 분리
public class AdditionalScanConfig {
    // ...
}
```

### 웹 MVC 설정 관리

#### 1. 슬라이스 테스트에서 제외되는 설정
```java
@Configuration(proxyBeanMethods = false)
public class WebConfig {  // @Configuration 클래스는 기본적으로 제외됨
    @Bean
    public WebMvcConfigurer configurer() {
        return new WebMvcConfigurer() {
            // ...
        };
    }
}
```

#### 2. 슬라이스 테스트에 포함되는 설정
```java
@Component  // 👍 @Component는 스캔 대상에 포함
public class WebMvcConfig implements WebMvcConfigurer {
    // ...
}
```

### 대안적 해결 방법

> [!tip] 설정 분리가 어려운 경우
> 1. 테스트에서 `@SpringBootConfiguration` 사용
> 2. 테스트의 `classes` 속성으로 명시적 설정
> 3. `@Import`로 필요한 설정만 선택적 포함

예시:
```java
@SpringBootTest(classes = TestConfig.class)  // 명시적 설정 클래스 지정
class MyTest {
    // ...
}
```

### 슬라이스 테스트 설정 확장

특정 슬라이스 테스트에 자동 설정 추가:

```none
# META-INF/spring/org.springframework.boot.test.autoconfigure.web.servlet.WebMvcTest.imports
com.example.CustomWebMvcConfig
```

> [!note] 설정 파일 위치
> - `META-INF/spring` 디렉토리에 위치
> - 파일명은 슬라이스 테스트 어노테이션의 전체 경로
> - `#`으로 주석 작성 가능

## 5. Spock 프레임워크 통합

> [!tip] Spock 사용하기
> - Spock 2.2 이상 버전 필요
> - `spock-spring` 모듈의 `-groovy-4.0` 버전 의존성 추가
> - Spring 테스트 프레임워크와 통합하여 사용 가능

의존성 추가 예시:
```groovy
testImplementation 'org.spockframework:spock-spring:2.2-groovy-4.0'
```
