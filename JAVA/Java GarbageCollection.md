
# Java 가비지컬렉션 (Garbage Collection)
## Garbage Collection(GC)이란?

GC는 JVM의 **힙(Heap)** 영역에서 더 이상 사용되지 않는 객체를 찾아 자동으로 메모리를 회수하는 기능입니다. 개발자는 C/C++처럼 직접 `malloc`·`free`를 호출하지 않아도 되므로, 비즈니스 로직에 집중할 수 있습니다.

---
### 장점
- **메모리 누수 위험 감소**  
    수동 해제 실수로 인한 크래시나 메모리 릭을 예방합니다.
    
- **개발 생산성 향상**  
    메모리 관리 부담이 줄어들어 코드 작성에 집중할 수 있습니다.
    
### 단점
- **해제 시점 제어 불가**  
    객체가 언제 회수될지 정확히 예측하기 어렵습니다.
    
- **Stop‑the‑World(STW) 지연**  
    GC가 실행되는 동안 애플리케이션의 다른 스레드는 잠시 멈춥니다.
    

> **STW(Stop The World)**  
> GC를 위해 JVM이 애플리케이션 실행을 일시 중단하는 구간을 의미합니다.  
> STW 시간이 길어지면 응답 지연이 발생할 수 있습니다.

## 가비지 컬렉션 대상

GC는 특정객체가 Garbage인지 아닌지 판단하기 위해 도달성, 도달능력(Reachability)이라는 개념을 적용한다. 객체의 레퍼헌스가 있다면 Reachable로 구분하고, 유효한 레퍼런스가 없다면 Unreachable로 구분해 수거해버린다.
* Reachable : 객체가 참조되고 있는 상태
* Unreachable : 객체가 참조되고 있지 않은 상태 (GC의 대상이 됨)

예를들어 JVM 메모리에서는 객체들은 실질적으로 Heap영역에서 생성되고 Method Area이나 Stack Area 에서는 Heap Area에 생성된 객체의 주소만 참조하는 형식으로 구성된다.

하지만 이렇게 생성된 Heap Area의 객체들이 메서드가 끝나는 등의 특정 이벤트들로 인하여 Heap Area 객체의 메모리 주소를 가지고 있는 참조 변수가 삭제되는 현상이 발생하면, 위의 그림에서의 빨간색 객체와 같이 Heap영역에서 어디서든 참조하고 있지 않은 객체(Unreachable)들이 발생하게 된다.

이러한 객체들을 주기적으로 가비지 컬렉터가 제거해주는 것이다.

## 언제, 어떻게 청소할까?

|   |   |   |   |
|---|---|---|---|
|알고리즘|영역|실행 조건|특징|
|**Copying**|Young|Eden 가득 참|단편화 없음, 빠름|
|**Mark‑Sweep‑Compact**|Old|Old 가득 참|단편화 해소, 느림|
|**Mixed (G1)**|Young+일부 Old|Young GC 후|Full GC 대체|
|**Concurrent (ZGC/Shenandoah)**|전체 힙|힙 압박 심할 때|

## 현대 GC의 변화

- 전통적 **Serial/Parallel GC** ⇒ GC 동안 완전 정지
    
- 최신 **G1, ZGC, Shenandoah** ⇒ **필요한 구간만 짧게 정지**하고 나머지는 애플리케이션과 **동시에** 청소하여 지연을 최소화합니다.
    

## 성능 관리(GC 튜닝) 포인트

1. **GC 로그 활성화** `-Xlog:gc`로 멈춤 시간·빈도 확인
    
2. **힙/영역 크기 조정** Young 영역이 작아 Minor GC가 잦다면 비율을 키우기
    
3. **객체 생존 기간 최소화** 불필요한 캐시·리스트를 조기에 정리
    
4. **적합한 수집기 선택** 일반 서비스는 G1으로, 밀리초 단위 지연이 민감하다면 ZGC / Shenandoah 고려
