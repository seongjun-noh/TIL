# 자바 메모리 구조
Java JVM의 메모리 영역은 크게 Method, Stack, Heap 세가지 영역으로 나뉘며, 각 영역에는 서로 다른 종류의 데이터가 저장되고 생명주기가 관리됩니다.

| 영역            | 저장 대상                                                | 생성 시점             | 소멸 시점                      | 구조/관리 방식                       |
| ------------- | ---------------------------------------------------- | ----------------- | -------------------------- | ------------------------------ |
| **Method 영역** | 클래스 바이트코드(메소드·필드 정보), **static** 변수, 런타임 상수 풀        | 애플리케이션 시작 시 로딩    | 프로그램 종료 시                  | 전역 저장소 (영구 영역)*; 클래스 로더에 의해 관리 |
| **Stack 영역**  | 메소드 호출 시 생성되는 **스택 프레임**(지역변수, 매개변수, 연산 중간 값, 복귀 주소) | 메소드 호출 시 프레임 생성   | 메소드 종료 시 프레임 제거            | LIFO(후입선출) 구조; 각 스레드별로 독립적     |
| **Heap 영역**   | `new` 키워드로 생성된 **객체**와 **배열**                        | 프로그램 실행 중 동적 할당 시 | GC(가비지 컬렉터)에 의해 참조 없을 때 회수 | 트리나 그래프 구조; 가비지 컬렉션으로 관리       |

## Method 영역
클래스 로딩 시점에 JVM 내에 로드된 클래스의 메소드 정보, 필드 정보, 그리고 런타임 상수 풀(문자열 상수, 클래스·메소드·필드 참조 등)이 저장됩니다.

`static`으로 선언된 변수들도 이 영역에 올라가며, 애플리케이션이 종료될 때까지 유지됩니다.

* 프로그램 전반에 걸쳐 공유되는 영역이므로, 모든 스레드가 이 데이터를 참조할 수 있습니다.
* 초기화 비용이 크므로 클래스 로딩 시점에 한 번만 수행됩니다.
## Stack 
메소드가 호출될 때마다 스택 프레임(Stack Frame)이 생성되고, 이 안에 그 메소드의 `지역변수`, `매개변수`, `중간 연산 결과`, 그리고 `리턴 주소`가 저장됩니다.

- LIFO 구조로, 가장 마지막에 호출된 메소드의 프레임이 가장 먼저 제거됩니다.
- 각 스레드마다 독립적인 스택을 가지므로, 멀티스레드 환경에서 지역변수는 Tread-safe합니다.
- 스택 크기를 초과하면 `StackOverflowError`가 발생합니다.

## Heap 영역
`new`키워드로 생성된 모든 객체 인스턴스와 배열이 이 영역에 저장됩니다.

- JVM 힙은 가비지 컬렉션(GC)에 의해 관리디며, 더 이상 참조되지 않는 객체를 자동으로 회수합니다.
- 힙 영역의 크기는 JVM 옵션(`-Xms`, `-Xmx`)으로 조절 가능합니다.
- 객체 간 참조 그래프 형태로 조작되며, GC 알고리즘에 따라 메모리 회수가 이루어집니다.
